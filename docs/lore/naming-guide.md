# 命名与文案指南：让玩家读懂魔法

版本：lore v0.2，2026-10-24。上游：[创作入口](README.md)、[世界设定](world.md)。本次更新规范，不修改现行252张卡牌的名称、效果、稳定ID或数值。

## 1. 三种文字各做一件事

- **卡名**：给出一个能记住、能画出来的物件、动作或现象，帮助识别卡牌。
- **效果文本**：准确说明发生什么、对谁发生、何时发生、持续多久，有哪些条件和上限。
- **风味文本**：表现人物和生活，可以幽默、含蓄，不承担效果解释。

界面必须能在不读背景故事的情况下使用。教程可以说“整理你的咒语书”，但规则解释仍明确“牌组”；不能让玩家靠理解诗句猜测效果。

| 竞技活动 | 魔法师大赛 | 大赛、比赛 | 不新造专名 |

旧称“环宴、环主、守环人、环印、战息、环刻、咏息、环纹、定环、环藏、亲咏、托咏、逆息”不进入新文案。自然语言中的“循环”、几何圆形和卡名本身不因此被禁用。

## 3. 卡名从生活里来，走向更大的魔法

普通卡可以来自日常技巧，稀有卡可以体现成熟手艺，史诗卡可以呈现大胆的研究成果，传奇卡应让人记住一项独特理论或强烈意象。稀有度不等同费用，不能靠名字擅自重分卡牌类别。

| 系 | 可用词源 | 适合的动作与意象 |
|---|---|---|
| 火 | 炉、窑、炭、火种、陶、余热 | 回火、积热、淬炼、开窑、火星聚拢 |
| 水 | 渡口、水槽、量杯、泉、潮、药液 | 导流、回流、蓄水、渗润、潮水往复 |
| 土 | 桥、砖、楔、陶印、石阶、地基 | 加固、承压、叠砌、回震、石块锁合 |
| 风 | 邮袋、风标、帆、织带、笛、羽 | 顺风、切风、追赶、穿过、节拍加快 |
| 毒 | 药草、菌、露、发酵罐、滴管、枯叶 | 浸渍、侵蚀、培养、分解、活性积累 |
| 通用 | 书签、批注、装订、目录、粉笔 | 翻阅、整理、校正、重读、寻找 |

以上是词源，不是已经获批的卡名或新卡。具体改名须先看实际机制，不为贴合职业强行把全部法术改成工具或家务。

卡名以口头好说、缩小好认、画面清楚为准，优先短名，不把字数当作凌驾于清晰度之上的硬限制。不依赖“终极、神级、超级”传达稀有度，也不对已有卡名追加机械的元素前缀。

## 4. 当前卡名如何处理

“回火、余火、灰烬账本、火种库”等已有名字具有手艺或研究意象，可作为评估起点，但本次不宣布全部保留。“炽焰王冠、不周山、天岚、万毒之源”等现行专精名仍照卡表识别，其新名称与画面需要在逐卡阶段单独讨论。

“弹仓、弹头、火药”等词可能带来枪械预期，“血统、战神、圣盾”等词可能让人联想到继承、神祇或阵营。后续逐卡核对是否需要替换，不为迁就名称虚构新世界规则。毒系可有锋利、危险的名字，不能把危害性自动解释成邪恶人格。

路线传奇的卡名、牌组别名和攻略用语应能相互对应，但不强制所有玩家给牌组起同一个名字。稳定ID是数据关联依据，中文名字不是主键。

## 5. 效果描述的完整性

每条效果先回答：**触发或使用条件 → 对象 → 操作与数值 → 时间窗口 → 次数或上限 → 例外**。多条效果分句，保留实际执行顺序。卡框放不下时考虑关键词解释、详情面板和排版，不通过删除限制词压缩文字。

审查必须区分：

1. 获取卡牌、首次打出、每次打出、确定专精、激活专精机制。
2. 本场持续与本局持有；传奇、路线传奇与能力牌，不能视为同义词。
3. 立即、下次抽牌阶段、下一发主弹、完整发射组与到期窗口。
4. 攻击力、基础伤害、减防后伤害、含护盾的伤害、实际生命伤害。
5. 回复量与实际恢复量；最大生命、当前生命与已损失生命。
6. 毒附魔层数与目标毒层，余烬与火附魔层，风系与已激活的风痕路线。
7. “若满足则执行，否则执行”与可以同时发生的两条独立效果。
8. “至多、每次、每场、累计、实际消耗、未兑换、上限”不能互相替代。
9. 取整方向、逐层结算、先后次序和同刻快照；文字与公式须与数值规范一致。
10. 移出本场牌组、弃牌、洗牌、置顶与直接抽取，不能统一写成“获得”或“消失”。

例如“回复7%生命”不完整：必须知道是最大、当前还是已损失生命的7%，以及是否逐次计算。若卡表、结算文档与实现有冲突，记录问题并查证，不凭文案常识选择一个新规则。

## 6. 播报、教程与风味示例

以下仅是表达示例，不是新增卡牌或已接入界面的文案：

- 开场：“欢迎来到魔法集会。整理好咒语书，大赛就要开始了。”
- 构筑：“下一位对手已经公布。看看你还需要哪些咒语。”
- 确定专精：“已确定火系专精，专精牌已加入牌组。”不要追加“余烬已经开始积蓄”。
- 淘汰：“本次比赛结束了。去喝杯茶，看看朋友们怎么打吧。”结果细节以系统真实状态为准。
- 回火的风味候选：“别急着熄炉，最好的火候有时在第二遍。”它不负责说明实际洗牌与余烬条件。

人物可用玩笑评论结果，系统提示应先说事实。不要用剧情玩笑掩盖刷新要花费研习点、路线被他人拿走或库存不足等重要信息。

## 7. 后续252张卡牌的改稿流程

1. 从唯一现行 cards.json 建立逐卡清单，以稳定ID对齐，记录现名、类别、费用、完整数值和效果。
2. 建立“现名 → 候选名 → 效果改写 → 风味文本 → 美术意象”的提案，不直接改冻结卡表。
3. 对照战斗结算、伤害、数值规范和构筑规则；涉及实现解释时再查对应执行逻辑。
4. 对语义不明确的条目单独列问题；保留原文、冲突来源与待确认点，不替用户补规则。
5. 审核改稿是否保持对象、条件、数值、窗口、次数和分支完全一致，检查近义撞名与检索可读性。
6. 名称与文案确定后，按项目版本流程同步卡表视图、路线引用、牌组和素材关联。使用稳定ID迁移，不能只改卡表名称造成其他文件失联。

建议提案字段：稳定ID、现名、候选名、采用理由、效果原文、改写文本、语义核对、待确认问题、风味候选、画面主体、确认状态。本次只准备规范，不宣称已完成逐卡审校。

## 8. 英文与本地化

中文先确定；英文作为语义对齐草案，不先锁定地名音译与游戏副标题。常用词草案为 Mages' Fair、Magicians' Tournament、Spellbook、Spell Page、Research Points。它们仅用于内部语义对齐，正式英文活动名与产品名后续确定。

机制关键词先建立一一对应词表，条件与时间表达跨语言保持一致；角色俏皮话可意译，规则文本不得因押韵或角色语气改变含义。
